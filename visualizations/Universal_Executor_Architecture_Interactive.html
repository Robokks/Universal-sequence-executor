    05 / Extension model
    Pluggable LabVIEW VIs. One supervisor.
    Support both small custom actions and complete specialized test procedures without handing away fault authority, command ownership or logging traceability.
    
        
    
          
    Custom Operation VI
    Type A
    Standard sequence
    Normal commands and conditions
    ⇄
    Custom VI
    One specialist action or calculation
    Example: a custom VTU test-result evaluation that receives selected measurements and returns a typed result, without controlling the entire test.
    
          
    Custom Test VI
    Type B
    Universal supervisor
    Start, monitor, interrupt, shutdown
    ⇄
    Test-specific VI
    Owns a specialized internal procedure
    Example: a highly specialized VTU test procedure that cannot be expressed through normal configuration, but still communicates through the common Bridge.
    
        
    
        
    Common plugin lifecycle
    Registered→Validated→Initialized→Running→Completed / Cancelled / Failed
    Start / Poll / Cancel / Status
    Typed inputs / outputs / errors
    Declared resource permissions
    Bounded response / heartbeat
    Result / capture correlation ID
    All commands via Bridge
    A separate LabVIEW VI is not necessarily process-isolated. The RT protection supervisor and hardware safety functions cannot depend on a plugin responding to cancellation.
    
        
    Runtime interaction example
    Executor / Plugin AdapterInvokes operation and receives results
    Bridge / ArbiterValidates resource authority
    RT Functional BlockExecutes permitted hardware action
    For cRIO deployments, plugin build inclusion, dependencies, RT runtime compatibility and dynamic loading are feasibility questions to validate in a prototype. This architecture does not assume arbitrary VI files can be hot-loaded.
